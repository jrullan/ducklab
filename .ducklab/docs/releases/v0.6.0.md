# v0.6.0

### Roster and Seating

- **Canonical roster board.** A unified roster view replaces the old Settings lineup chips. Assign ducklings to roles by drag-and-drop or keyboard, see where each assignment comes from (global vs. project-pinned), and override per-run from any launcher without changing your saved roster.
- **Seat-aware candidate suggestions.** When you select a seat on the roster board, the flock list reorders to surface the best candidates with evidence explaining why each was suggested.
- **Duckling scorecards.** Each duckling now has a scorecard built from engine evidence — filter and sort the flock by scorecard data to choose the right model for a role.
- **Roster management via MCP.** External operators can read and manage the canonical roster through the MCP interface, with the same candidate suggestions and provenance labels.
- **Scoped roster boards.** Roster boards render scoped to their context, so you see the seats that matter for the task or stage you're working on.
- **Launcher seat prefill.** Task, TDD, and stage launchers prefill seat chips from the canonical resolver and label each as project or global provenance, so you always know what you're overriding.

### Acceptance and Verification Gates

- **Clean-checkout acceptance gate.** Accepted runs now record clean-checkout verification results on the run record, so you can see that a committed change reproduces from a fresh checkout — with your project's installed dependencies linked in, not rebuilt from scratch.
- **Stage-appropriate gate enforcement.** The clean-checkout gate now enforces the right result for the stage: red for test-first runs, green for builds — no more ambiguous pass/fail on reproduction.
- **Acceptance blocked on missing ignored files.** If a committed checkout omits required git-ignored files (like `.env` or generated configs), acceptance is rejected with a clear reason instead of failing silently downstream.
- **Reject cleanup protects later commits.** Rejection no longer restores paths over commits that landed after the run's snapshot, preventing accidental clobbering of work done while the run was in flight.

### Provider and Run Resilience

- **Orphaned restart recovery.** Restart checkpoints left orphaned after a deadline are recovered, and operators get a resume path to pick up where things left off.
- **State isolation for verify runs.** Every verification process tree now gets isolated state environment variables, preventing project-level env from leaking into gate results.
- **Shared Go caches preserved.** Gate state is isolated while shared Go build caches are preserved, so verification stays clean without slowing down compile times.
- **Compile-red detection ignores download chatter.** Test specifications that fail to build are rejected unless the package compiles and the new test genuinely fails by assertion — noisy download output no longer trips the detector.

### Autopilot and Guidance

- **Autopilot attributes correctly.** Yolo auto-accept decisions are now attributed to the autopilot, not to a human — so the audit trail reflects who actually decided.
- **Guide skips human-only steps.** The project guide skips steps that require human judgment and jumps straight to the first mechanical task, so autopilot and operators waste no time on steps they can't take.
- **Verify guidance prioritized.** For fixed bugs awaiting verification, the guide now prioritizes Verify over Reopen, so the natural next step comes first.
- **Release guidance counts only accepted work.** Release planning now counts only accepted work included in the latest release, so the numbers reflect what actually shipped.
- **No-changes builds count as settled.** Accepted builds that produced no changes are counted as settled and blocked from automatic relaunch, preventing infinite loops on empty work.

### Loop Rails and Repetition Detection

- **Per-file fs_patch failure brake.** A consecutive failure brake on `fs_patch` per file stops runs from hammering the same patch repeatedly, with health reporting and guidance pointing to `fs_write` or `fs_write_lines` as the remedy.
- **Repetition detection in streaming fallback.** The unsupported-streaming fallback path now runs the same repetition detection as the streaming path, so loops are caught regardless of provider mode.

### Roster Provenance and Identity

- **Git-derived build version.** The CLI, engine, and MCP all report a git-derived build version with provenance, so you can verify exactly what code is running.
- **Safe engine version command.** A dedicated version command reports engine identity without risk of overwriting the live engine's identity.
- **Seat provenance exposed.** Every seated role records and exposes its provenance — global default, project pin, or per-run override — so you can trace why a particular duckling was in a seat.

### Desktop

- **Stale stream reconnection.** The desktop now reconnects stale event streams and reports stream health, so the UI doesn't silently freeze when the connection drops.
- **Stale engine binding recovery.** Stale desktop engine bindings are recovered automatically, and failed actions are surfaced instead of disappearing.
- **Bounded streamed state.** Streamed run state is bounded and summary-only board refreshes are debounced, keeping the desktop responsive even under heavy event load.

### Triage and Bug Lifecycle

- **Sibling triage resolution.** Accepting a newer triage run automatically resolves sibling paused triage runs for the same bug, so you don't end up with competing triages.
- **Human answer state mapping.** Human answer events now correctly map to running status and clear pending state, preventing runs from getting stuck in a paused state after you answer.
- **Redo notes on failed runs.** Failed-run decision cards now show an advisor-attributed redo note explaining what went wrong and what reshuffle is suggested, so you know what to change before relaunching.
- **Advisor distress routing.** Implementer distress signals are routed to the advisor, and reviewer-safe operational summaries are exposed so the reviewer sees the signals as data without the implementer's reasoning.

### Contracts and Token Limits

- **Removed 2048-token cap on decomposition.** The `json:decomposition` contract no longer has a hard 2048-token output cap, and sampling now enforces its own output cap consistently — so larger decompositions aren't artificially truncated.

### MCP

- **Per-run seating and turn overrides.** MCP task launchers now accept per-run seating and turn cap overrides, giving external operators the same launch flexibility as the desktop.
- **Unified omitted-mode resolution.** When a mode is omitted at launch, desktop, autopilot, and MCP all resolve it the same way — no more inconsistent defaults depending on which client started the run.

### Spec Debt

- **Unimplemented tasks marked as spec debt.** All accepted but unimplemented tasks are now marked as spec debt, and `spec_settle` documents them — so the spec reflects what was actually delivered and what still needs wiring.

## Also in this release — built by hand, beside the loop

These landed as direct commits between v0.5.0 and this tag, while the loop
built the tasks above. They are documented in the spec (SPEC-021/024/026,
SPEC-056..060) and ADR 0008.

### The rubber duck and the work contract

- **The advisor is a positioned turn.** After the implementer's turn closes
  and before the reviewer speaks — and only on measured distress (brake
  refusals, failure streaks, red gates, undelivered items) — the advisor
  reads what the reviewer must not and answers one of three ways: `none`; a
  `note` that sends the implementer straight back to work before any reviewer
  turn is spent (bounded to two retries per round); or `stop`, which pauses
  the run with its work in place and a redo note born with the reshuffle. The
  reviewer receives telemetry as data only.
- **`ask_advisor`.** The implementer's mid-turn consult: answers inline,
  never pauses, no human involved.
- **The deliverables checklist.** The task's numbered bullets are the
  implementer's work contract; it reports each by number at the end of its
  turn. Undelivered items summon the duck; the reviewer gets ids and statuses
  as a rubric, never the notes; an approve over undelivered items is recorded
  as a gap. The desktop renders the report as a checklist inside the
  implementer's turn (folded turns show `☑ n/m ›`) and flags the gap on the
  reviewer's verdict.
- **Reviewer round memory.** From the second round on, the reviewer is told
  what changed since it last read and what it read then.
- **`fs_write_lines`.** A ranged write addressed by the line numbers
  `fs_read` shows, with a proof-of-reading field that teaches the actual line
  on mismatch — the middle ground between `fs_patch` and whole-file
  `fs_write`. The fs_patch brake names it as the remedy.

### Roster, evidence and suggestions

- **Per-mode project seats.** A project pins seats per mode
  (`[mode_seats.<mode>]`), Common roles as role pins; the resolver's
  precedence is request → project mode seat → project pin → global mode seat
  → global role pin → engine pick; the mode travels with every launch;
  required seats refuse a launch, cardinality warns at write. Global and
  project boards write to their own scope; empty-list clears; unpin re-reads.
- **Scorecards.** `GET /v1/ducklings/scorecards`: declared cost/caps, measured
  evidence (overall and **per seat held**), latest bench, and an external
  index. The **coding / intelligence / agentic indices come from OpenRouter's
  benchmarks endpoint** (Artificial Analysis) for OpenRouter ducklings nobody
  declared one for — matched by the permaslug OpenRouter serves for the id,
  cached a day, source and as-of on every number; a declared index is never
  overwritten; a local model never borrows one.
- **The Flock as an instrument.** Compact cards ordered by evidence (pass
  rate first), filter chips (provider · local/remote · vision/tools · ≥128k/
  256k/1M), one direction toggle, a count that says "3 of 12 · clear", one
  evidence grammar everywhere (`84% · 198 runs · $0.21/run · coding 68.8`,
  "· few" under five runs, no price for locals), model and list price on
  hover. Flock and boards scroll independently.
- **Seat suggestions you can trust.** One ranking rule in the engine
  (`RankCandidates`); MCP and desktop pass it through. **The criteria are
  yours**: a catalog (coding/intelligence/agentic index, pass rate in this
  seat, pass rate overall, cost per run, wallclock, bench, input/output
  price, context), a default order per role, and
  `[defaults.candidate_criteria]` to reorder per role or switch a seat off —
  edited in place on the Roster ("criteria"). Pass rates rank by the lower
  bound of their Wilson interval (3 of 3 is not "100%"), measured criteria
  need three runs, a duckling qualifies only with a value for the first
  criterion, declared `roles` are respected, locals are not compared on price.
  Seats show their occupant's evidence in that seat, "✓ suggested" when the
  occupant is the top pick and "suggested: X" (one click) when it is not.
- **Board as a decision surface.** Occupied seats carry one small "+", empty
  ones the drop zone; remove is a quiet ×; role headers in small caps; the
  mode bar is amber only when the mode is not runnable (reason beside the
  title); Common sits first, without a bar; the drag image is a name chip at
  the cursor and the hovered column lights up.

### The loop, honest at its edges

- **Nothing lands that did not reproduce (B-069).** An accept whose commit
  fails the clean-checkout gate takes its own commit back (soft reset, only
  while it is still HEAD), keeps the diff in the tree, records
  `commit_withdrawn`, and leaves both decisions open — before, such a run
  could be neither accepted (same red sha forever) nor rejected ("a commit
  landed since": its own).
- **Architecture tests are cache-honest (B-070).** They read the sources
  themselves instead of shelling out to `go list`, so Go's test cache sees
  every import edge — the in-run gate no longer approves what the checkout
  will refuse.
- **Clean-checkout acceptance** borrows the live tree's `node_modules` and
  `.venv` (by marker files, `pytest.ini` included); a failed auto-accept
  pauses at the human gate wearing the error instead of stranding the run.
- **The release scribe gets substance (B-071).** Each inventory item carries
  the task's own summary, so the scribe writes instead of reading forty-five
  tasks one call at a time.

### Desktop

- The task's description folds into the run header (▸ on its title), pinned
  while the transcript scrolls; the pause divider; `ask_advisor` advice inline;
  the tool timeline counts `fs_write_lines` as a write and the `*_read` /
  `*_list` family as reads.
- The guide rail groups its steps (one "Verify 3 fixed bugs" with the ids as
  chips, not three lines), headlines the first, shortens the rest, folds past
  four, and starts as its strip beside views where nothing is acted on in
  place. Roster lives once, under Config. Releases has a "Draft next release"
  door beside the list and no longer shows a stale draft of a cut version.
- Launch defaults: caps for tokens and wallclock are lifted at every build
  launch and `agent_turns` sits at 50–60; the USD cap is the guard.
